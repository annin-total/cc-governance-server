# UI デザイン設計

集計サーバの画面に適用するデザインシステムと、その実装計画である。

## 1. 目的と範囲

**目的**: 管理者が数値を**誤読せずに**読み取れる画面にする。見た目の水準は、
社内で先行運用していた利用ログサーバと同等以上に揃える。

**範囲**: 表示層のみを対象とする。集計ロジック・SQL・ルーティング・収集項目は変更しない。
表示のための整形（日付・桁区切り・単位）は表示層の責務として本設計に含む。

**この画面を見るのは管理者だけである。**したがって装飾を足さない。
デザインの労力は、**どの数字がどの母集団の、どの期間のものかを取り違えさせないこと**に使う。

---

## 2. 現行の集計項目

画面は 4 つ。データは `events`（19 列）、`policy_state`（10 列）、`cost_daily`（13 列）の
3 テーブルから作られる。

### 2-1. 概況 `/`

| 指標 | 内容 | 期間の窓 | 分母 |
| --- | --- | --- | --- |
| 健全性 | イベント件数・送信端末数 | 直近 7 日と前 7 日 | — |
| NULL 率 | `tool_name` / `skill_name` / `context_tokens` / `command_source` の 4 列 | 同上 | その窓の全イベント |
| 突合率 | `events` を送った利用者のうち `cost_daily` にも居る割合 | 直近 7 日 | **events を送った利用者数** |
| plugin_version 分布 | 端末ごとの最新 1 行の版を数える | 直近 30 日 | — |
| 日次コスト | `day` × `provider` のコスト合計 | **全期間（窓なし）** | — |
| 利用者・セッション推移 | `day` 別の利用者数・セッション数 | 直近 14 日 | — |
| 分布 × 3 | `permission_mode` / `effort_level` / `source` の件数 | 直近 7 日 | — |
| 取込結果 | CSV 取込の成否と行数・破棄件数 | 操作時のみ | — |

### 2-2. policy `/policy`

施策項目は `contract.POLICY` の 2 つ。

| 施策項目 | 期待値 |
| --- | --- |
| `env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` | `60` |
| `extraKnownMarketplaces.cc-marketplace-governance-bmsd.autoUpdate` | `true` |

| 指標 | 内容 | 期間の窓 | 分母 |
| --- | --- | --- | --- |
| 最後に観測した値 | 端末ごとの最新 1 行 | 直近 30 日 | — |
| 準拠率 | 施策項目ごと。**1 台でも未準拠なら、その利用者は未準拠** | 直近 30 日 | **直近 30 日に `cost_daily` にコストが立つ利用者数** |
| 未準拠者の一覧 | 最新 1 行の `prev_value` が期待値と違う端末 | 同上 | — |
| 未導入者の一覧 | `cost_daily` に居て `policy_state` に 1 行も無い利用者 | 同上 | — |
| 途絶えた端末 | 最終観測日が 14 日以上前 | 同上 | — |
| plugin_version 分布 | 端末ごとの最新 1 行 | 同上 | — |

### 2-3. effect `/effect`

基準の施策項目は `env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`、対象 provider は `aws-bedrock`。

| 指標 | 内容 | 注意 |
| --- | --- | --- |
| イベントスタディ | 準拠開始日を 0 とした相対日 −14〜+14 の、1 人あたりコストと入力トークン | **相対日 0 は意図的に除く。**分母人数は相対日ごとに変わる |
| コンテキスト分布 | `context_tokens` を 20,000 刻みで、準拠開始日の前後に分けて数える | `PreCompact` と `Stop` の 2 系統。**度数 0 のビンは返さない** |

### 2-4. assets `/assets`

| 指標 | 内容 | 期間の窓 | 分母 |
| --- | --- | --- | --- |
| スキル別 | `skill_name` 別の呼出回数・利用者数 | 直近 7 日と前 7 日 | — |
| コマンド別 | `command_name` × `command_source` 別 | 同上 | — |
| サブエージェント率 | `agent_id` が非 NULL のイベントの割合 | 直近 7 日 | **その窓の全イベント** |

### 2-5. ここから導かれる設計上の要請

集計項目を並べると、**誤読の危険が 4 つ**はっきりする。画面設計はこれに応える。

1. **`day` は epoch 日（整数）である。**そのまま描画すると `20005` と出る。人間には読めない
2. **3 つの窓が同じ画面に混在する。**7 日（events 系）・14 日（推移）・30 日（policy 系）、
   そして日次コストだけが**窓なしの全期間**である。断りがなければ同じ期間だと誤読される
3. **「率」の分母が 4 種類ある。**イベント数・利用者数・events を送った利用者数・
   コストが立つ利用者数。どれも「％」としか書かれていない
4. **相対日 0 の欠落と、度数 0 のビンの欠落は仕様である。**説明が無ければ障害に見える

**数字のそばに、その数字の母集団と期間を書く。**これが本設計の中心にある。

## 3. 現行の表示

`templates/base.html` は 26 行で、`sans-serif`・1px の灰色格子・`#4a90d9` の棒のみを持つ。
デザイントークンもコンポーネント語彙も無い。`day` は生の整数で描画される。
桁区切りも単位も無い。空状態は `effect` の 4 箇所にのみある。

## 4. 制約

### 4-1. テストが HTML を正規表現で読んでいる（最重要）

ビューのテストは HTML パーサを使わず、**正規表現で HTML を直接照合している**。

| 前提にしている形 | 破ってはいけないこと |
| --- | --- |
| `<table data-testid="...">` | **`<table>` に属性を足さない。**`data-testid` が最初の属性でなくなるとマッチしない |
| 裸の `<tr>` | **`<tr>` に属性を足さない。**足すと行数が 0 になり、件数の検査が全滅する |
| `assert "<td>None</td>" not in html` | 該当する列の `<td>` は裸のままにする |

**この制約は設計を縛らない。**採用するデザインはテーブルに `.tbl` というラッパーを与え、
表そのものは `table` / `th` / `td` の**要素セレクタ**で整える。表に class は要らない。
**テストを 1 行も変えずに表の見た目が変わる。**

### 4-2. 文字列を検査している箇所

次の 2 つは**表示形式を変えるとテストが落ちる**。変更する場合はテストの更新を同じ段に含める。

| 箇所 | 検査 |
| --- | --- |
| 概況の健全性 | `"イベント 13 / 3"` `"送信端末 4 / 3"` |
| 概況の plugin_version | `"1.4.0:5"` `"1.3.0:2"` |

一方、**次は自由に変えられる**（テストが表記を見ていない）。

- **`day` の表示形式**（`20005` → `2024-10-09`）
- **数値の桁区切り**（トークン数・件数）
- **コンテキストのビンの表示**（`20000` → `20k–40k`）

率の表記（`15.4%` `75.0%` `20.0%` `80.0%`）と、`aws-bedrock` / `openai` / `project` /
`user` / `/no-source` / `u4` の各値はテストが検査しているため、**小数 1 桁と生値を保つ**。

### 4-3. リポジトリの規約

- **依存を増やさない。**CSS フレームワークもビルド工程も導入しない
- **Web フレームワークに依存するのは `app.py` だけ**
- **Python 3.9 で動く**こと
- **コードファイルは 200 行以内を目安**とする

## 5. デザインシステム

先行実装のトークンと語彙を土台に、**管理画面として読み違いを減らす方向にだけ**手を入れる。

### 5-1. 色

白地・ティール系アクセント・状態 3 色という構成を継承する。
状態色は濃色（文字）と淡色（背景）の対で使う。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--bg` | `#fff` | ページ背景 |
| `--surface` | `#f5f7f8` | タイル・見出しセル・チップの背景 |
| `--line` | `#e1e6e8` | 罫線・枠線 |
| `--ink` | `#121a1e` | 本文 |
| `--ink2` | `#44525a` | 副次的な文字（コントラスト 7.96:1） |
| `--muted` | **`#5f6c73`** | 補足・単位・見出しセルの文字（**5.42:1**） |
| `--accent` / `--accent-soft` | `#0e6b6b` / `#e3f1f0` | リンク・主ボタン・メーター（6.30:1） |
| `--ok` / `--ok-soft` | `#1f7a4d` / `#e5f4ec` | 準拠・成功 |
| `--ng` / `--ng-soft` | `#b42318` / `#fdecea` | 未準拠・失敗 |
| `--warn` / `--warn-soft` | `#a16207` / `#fef6dd` | 注意・未導入・保留 |

`--muted` だけ先行実装の `#6f7c83` から変える。**`#6f7c83` は白地でコントラスト 4.30:1 であり、
WCAG AA の 4.5:1 を満たさない。**補足文を 12px で組むため実用上も読みにくい。
`#5f6c73` にすると 5.42:1 になり、見た目の印象はほとんど変わらない。

> `--warn` を `--warn-soft` 上で使うと 4.56:1 で AA をかろうじて満たす。
> **`.pill` や `.note` の文字を 12px より小さくしない。**

### 5-2. 尺度

先行実装は余白・角丸を直値で書いていた。**トークン化して段階を固定する。**
値の種類が増えるのを防ぎ、画面間のばらつきを消す。

| トークン | 値 |
| --- | --- |
| `--sp-1` 〜 `--sp-6` | `4px` `8px` `12px` `16px` `24px` `32px` |
| `--r-sm` / `--r-md` / `--r-pill` | `6px` / `10px` / `999px` |

### 5-3. タイポグラフィ

本文 `14px/1.7`、和文優先スタック
（`"Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", system-ui, sans-serif`）。

**見出しの階層を先行実装より明確にする。**先行実装は `h2` が 16px で本文 14px と差が小さく、
節の切れ目が視覚的に弱い。1 画面に節が 5〜7 個ある現行では、これが読みにくさに直結する。

| 要素 | 指定 |
| --- | --- |
| `h1` | 22px / 700 |
| `h2` | 15px / 700 / `--muted` / `letter-spacing: .04em` / 上罫線 + `--sp-5` の上余白 |

**`h2` を大きくするのではなく、色と罫線で区切る。**管理画面では見出しが大きいほど
情報密度が下がる。罫線 1 本のほうが節の境界を強く示せる。

数値には `font-variant-numeric: tabular-nums` を当てる。

### 5-4. コンポーネント

| クラス | 役割 |
| --- | --- |
| `.tiles` / `.tile` | KPI の並び。`<b>` が数値（26px）、`<span>` がラベル（12px・muted） |
| `.tile .delta` | 前期間との差。増減の向きを記号（`+` / `−`）と色で示す |
| `.tbl` | 表の外枠。`overflow-x: auto` + 枠線 + `--r-md` |
| `.tbl th` | 見出しセル。`position: sticky; top: 0` で**縦スクロール時も残す** |
| `td.num` | 数値セル。右寄せ + タブラー数字 |
| `.pill` | 状態ラベル。**修飾子は `.ok` / `.warn` / `.ng` / `.neutral` の 4 つだけ** |
| `.meter` / `.meter i` | 率の横棒。`i` の `width` が率 |
| `.chips` / `.chip` | 母集団と期間の明示（後述） |
| `.btn` / `.btn.primary` | ボタン |
| `.note` / `.err` / `.ok-box` | 注意・エラー・成功の帯 |
| `.lead` / `.muted` | 見出し直下の説明 / 補足 |
| `.empty` | 空状態。文言と次の操作への導線を含む |
| `.bar` / `.brand` | ヘッダの横並びと製品名 |
| `nav a[aria-current="page"]` | 現在地。画面を行き来するため常に示す |
| `.grid` | 2 つ以上の塊を横に並べる。`effect` の前後比較に使う |
| `.delta` / `.up` / `.down` | 増減。**タイルの中でも表の中でも同じ見た目にする** |

`tile` マクロは `note` を取り、率の分子・分母をタイルの中に収める。
率をタイルで見せる節では、同じ値をタイルの外にもう一度出さない。

**`.pill` の修飾子は意味ベースにする。**先行実装は `.pill.applied` `.pill.compliant`
`.pill.not_applied` のように**状態名そのもの**を修飾子にしていた。現行の集計項目に
その状態名は存在せず、項目が増えるたびに CSS を触ることになる。
`.ok` / `.warn` / `.ng` / `.neutral` の 4 つに固定し、**どの状態をどの色に写すかは
テンプレート側で決める**。

### 5-5. 母集団と期間の明示

2-5 で挙げた誤読に、コンポーネントで応える。

**すべての `h2` の直下に `.chips` を置き、その節の期間と母集団を書く。**

```
直近 7 日  ·  分母: この期間にイベントを送った利用者
直近 30 日  ·  分母: この期間にコストが立つ利用者
全期間  ·  窓なし
```

率を出す箇所では、**`.meter` の右に必ず「分子 / 分母」を併記する**。
`75.0%` だけを見せない。`75.0% (3/4)` の形にする。

### 5-6. 表の挙動

先行実装は全セルに `white-space: nowrap` を当てていた。`user_email` と `command_name` が
長い現行のデータでは、**横スクロールが常態化して読めなくなる**。

- `nowrap` は**数値列と日付列にだけ**当てる
- 文字列列は折り返しを許し、`max-width` で頭打ちにする
- 見出しセルを `sticky` にして、縦に長い一覧でも列名を見失わない
- **枠と表を内容幅にする**（`.tbl` は `width: fit-content; max-width: 100%`、`table` は `width: auto`）。
  列が 2〜3 しかない表を画面幅いっぱいに広げると、値と値の間が空いて対応が読み取れなくなる
- `caption` は折り返さない。狭い表で caption だけが縦に伸びるのを防ぐ

### 5-7. 操作の可視化

先行実装にはフォーカスの可視化が無い。**キーボード操作で現在地が分からない。**

```
:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }
```

を全体に当てる。表には `<caption>` を、見出しセルには `scope` を付ける。
どちらも `<table>` / `<tr>` の属性ではないため、4-1 の制約に触れない。

## 6. 表示の整形

`day` の変換と桁区切りは表示層の責務である。**集計クエリは触らない。**

`formatting.py` を新設し、`app.py` で Jinja フィルタとして登録する。
フレームワークに触れるのは登録の 1 行だけで、変換関数自体は素の Python に保つ。

| フィルタ | 入力 | 出力 | 根拠 |
| --- | --- | --- | --- |
| `day` | `20005` | `2024-10-09` | `contract.to_day` の逆変換（JST 基準） |
| `num` | `1234567` | `1,234,567` | 桁区切り |
| `usd` | `12.3` | `$12.30` | コストは小数 2 桁 |
| `pct` | `75.0` | `75.0%` | **小数 1 桁を保つ**（4-2） |
| `bin` | `20000` | `20k–40k` | ビンの下限値から範囲を組み立てる |
| `rel` | `-3` / `3` | `−3 日` / `+3 日` | 相対日。符号を明示する |

`None` は各フィルタで `—`（em dash）に統一する。現行は `"未設定"` と `"—"` が混在する。
**ただし `policy` の「最後に観測した値」だけは `"未設定"` を保つ**（テストが検査している）。

## 8. 画面別の適用計画

### 共通

ヘッダ（ブランド + ナビ 4 項目）、フッタに出典を常時表示する。

> 端末からの自己申告値。コストとトークンは全社 CSV を正とする。
> 監査・人事評価・勤怠管理には使わない。

**この一文を常に画面に置く。**集計値の転用を設計で防ぐ。

### 概況 `/`

| 現行 | 適用後 |
| --- | --- |
| 健全性が `<p>` に 6 指標を詰め込み | `.tiles` に分解。イベント・送信端末・突合率を独立したタイルにし、前期間差を `.delta` で示す |
| NULL 率 4 列が文章の中 | 1 つの表にまとめ、`.meter` で率を可視化。**NULL 率は高いほど悪い**ため、20% 超を `--warn`、50% 超を `--ng` で塗る |
| plugin_version が `1.4.0:5` の羅列 | 表に変換（版・台数・割合） |
| 取込結果が成功も失敗も同じ `<li>` | 成功は `.ok-box`、失敗は `.err` に分ける |
| 日次コストの `day` が生数値 | `\|day` で日付に。コストは `\|usd`。**「全期間・窓なし」を `.chips` で明示** |
| 5 つの表が裸 | `.tbl` で包む |

**テスト影響**: 健全性のタイル化で 2 件、plugin_version の表化で 2 件、計 4 件の更新が要る。

### policy `/policy`

| 現行 | 適用後 |
| --- | --- |
| 準拠率が数値と `.rate-bar` | `.meter` + `75.0% (3/4)` の併記。**分母の定義を `.chips` に明記** |
| 施策項目名が生のドット区切り | 生値を保ちつつ、`.muted` で人間向けの説明を併記 |
| 未準拠 / 未導入 / 途絶が同じ見た目の表 | `.pill` で区別（未準拠 `.ng`、未導入 `.warn`、途絶 `.warn`） |
| 一覧が空でも空の表が出る | `.empty` に置き換え、「この期間に該当なし」と書く |

> **未準拠者の一覧だけは 0 件でも表を出す。**この表は `data-testid` と `data-key` の組で
> 行数を検査されており、`.empty` に差し替えると検査対象の要素が消える。
> 4-1 の DOM の形を優先する。
| `day` が生数値 | `\|day` |

**「1 台でも未準拠なら利用者は未準拠」という判定規則を `.note` で明記する。**
台数と人数が一致しない理由がこれである。

### effect `/effect`

| 現行 | 適用後 |
| --- | --- |
| 相対日が `-14`〜`14` の生数値、0 が無い | `\|rel` で `−14 日`。**「相対日 0 は準拠当日のため除外する」を `.note` で明記** |

| `.rate-bar` の幅が `cost * 10` の即席計算 | `.meter` に統合し、**その列の最大値を 100% とする相対表現**に改める |
| 空状態が「準拠前: データなし」の 1 行 | `.empty` に統一。**検査対象の文字列は保つ** |
| ビンが `20000` の生数値 | `\|bin` で `20k–40k`。**「度数 0 のビンは表示しない」を `.note` で明記** |
| before / after が別々の表で比較できない | 同じビン軸の 2 列に並べ、横並びで比較できるようにする |

## 9. 実装計画

各段の終わりに `.venv/bin/python -m pytest -q` と `.venv/bin/ruff check .` を通す。
**段を飛ばさない。**前段が緑にならないまま次へ進まない。

### 段 1: 土台（テンプレートの中身に触らない）

1. `static/app.css` にトークン・土台・コンポーネントを書く
2. `base.html` にヘッダ・フッタ・`<link>` を入れ、既存の `<style>` を削除する
3. `BASE_PATH` を設定した状態で CSS が 200 で返ることを確かめるテストを 1 件足す

**検証**: 既存テストが全件緑のまま、配色・余白・表の見た目が変わる。
**この段だけで見た目の変化の大半が終わる**（要素セレクタが効くため）。

`url_for("static", ...)` は `SCRIPT_NAME` を前置するため、`BASE_PATH` の有無にかかわらず
正しい URL を返す（実測で確認済み）。**参照先が壊れても画面は 200 のまま素の HTML になり、
見た目だけが崩れて気づきにくい。**回帰テストで参照先を実際に引いて確かめる。

### 段 2: 表を包む

各画面の `<table>` を `<div class="tbl">` で包み、`<caption>` と `th` の `scope` を足す。
**`<table>` と `<tr>` には触らない。**

**検証**: 既存テストが全件緑のまま。ウィンドウを狭めて横スクロールを確認する。

### 段 3: 整形フィルタ

1. `formatting.py` を作り、6 つの関数を単体テストつきで書く
2. `app.py` でフィルタとして登録する
3. 各画面の `day` ・数値・ビン・相対日にフィルタを当てる

**検証**: 既存テストが全件緑のまま（4-2 のとおり、これらの表記は検査されていない）。
**`formatting.py` の単体テストは、境界値（`None`、0、負の相対日、うるう年）を含める。**

### 段 4: コンポーネントの適用

1. `_macros.html` にマクロを定義する
2. `.rate-bar` を `.meter` に置き換える
3. `.chips` で各節の期間と母集団を明示する
4. 概況の健全性をタイルに、plugin_version を表にする — **同じ段で該当テスト 4 件を更新する**
5. `.pill` と `.empty` を適用する

**検証**: 更新した 4 件のテストが、更新後の DOM に対して**意味のある検査になっているか**を確かめる。
タイルの値を意図的に別の変数に差し替えて、テストが落ちることを見る。
**落ちないなら、そのテストは何も守っていない。**

### 段 5: 仕上げ

`.note` による仕様の明示（相対日 0 の除外、度数 0 のビン、準拠判定の規則）、
フォーカス可視化、NULL 率のしきい値による着色。

**検証**: 4 画面をブラウザで開き、各節の `.chips` に書かれた期間と母集団が、
`queries_*.py` の実装と一致しているかを 1 つずつ突き合わせる。
**ここは自動テストでは守れない。目視で確かめる。**

## 10. 採否

| 提案 | 採否 | 理由 |
| --- | --- | --- |
| 数値セルの右寄せ・タブラー数字 | **採用** | 桁の比較が一目でできる |
| 空状態の統一 | **採用** | 現行は `effect` のみ |
| 出典と限界の明記 | **採用** | 集計値の転用を防ぐ |
| `<caption>` と `scope` | **採用** | 費用が小さく、表の意味が明確になる |
| フォーカス可視化 | **採用** | 現状は完全に欠落している |
| `--muted` のコントラスト修正 | **採用** | AA 未達の是正 |
| 見出しの階層強化 | **採用** | 1 画面に節が 5〜7 個ある |
| 母集団・期間の明示 | **採用** | 本設計の中心 |
| ダークモード | **見送り** | 管理者だけが見る画面であり、状態色 6 つのコントラスト再設計に見合わない。トークン方式のため後から足せる |
| 印刷用スタイル | **見送り** | 需要が確認できてから |
| グラフ描画 | **見送り** | 依存が増える。`.meter` で足りる |

## 11. 未検証事項

- コントラスト比は WCAG 2.1 の相対輝度式による計算値であり、実機の表示で測っていない
- `sticky` な見出しセルが `overflow-x: auto` の内側で意図どおり働くかは、
  縦に長い表を実データで表示して確かめていない
- 画面幅を狭めたときの折り返しは確かめていない。管理者の画面であり、想定は広い画面である
- **突合率には前期間との差を出していない。**集計が当期の値しか返さないためであり、
  差を出すなら集計側の変更が要る
- 先行実装の画面を実際に描画して比較していない。継承したのは CSS とテンプレートの読解による
